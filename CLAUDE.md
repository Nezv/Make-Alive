# Zombie Extraction — LAN multiplayer FPS (Godot 4.7, GDScript)

Early development. One test map (an L-shaped corridor), hordes of zombies that come apart.
Everything is code: no editor-made scenes. Most models are built from boxes in GDScript; character models (the zombies' outfits, the bodies under them, the skeleton) are generated by Python scripts run in Blender (`tools/models/`) into `assets/models/` — never edit those files by hand, change the script and re-run it.

## Commands (PowerShell, from the project folder)
- `tools\test.ps1` — run all tests headless (~2.5 min). `tools\test.ps1 zombie` runs only matching tests. **Run after every change.**
- `tools\godot.ps1` — play. `tools\godot.ps1 -e` opens the editor.
- `tools\godot.ps1 -- --host --demo` — zombie line-up right in front of you, no hordes (for looking at animations).
- `tools\play2.ps1` — two windows on one PC, host + guest, to test multiplayer alone.
- `tools\balance.ps1` — print every gun against every zombie type and write `references/balance.md`. `tools\perf.ps1 [map] [seconds] [mission]` — real frame times and draw calls in a window with 60 zombies. `tools\shots.ps1 [filter]` — the standard screenshots into `references/shots/` with a contact sheet (`index.html`); read them after a visual change.
- Other options after `--` (see top of `scripts/main.gd`): `--join=IP`, `--bot`, `--bot-aim=head|legs|arms`, `--no-fire`, `--spawn=N`, `--no-hordes`, `--quit-after=S`, `--screenshot=PATH --shot-at=2,4`, `--weapon=1..9`, `--pose=aim|sprint|reload|shove`, `--limited-ammo` (reloads take from a reserve even on a test map), `--gun-rack` (all nine gun models side on), `--fx-rack` (every effect looping in a row), `--noise` (rings where noise happened), `--director` (the pacing as text), `--wheel` (the item wheel up), `--zones` (draw the map data: zones, zombie closets, routes, spawns), `--bot-goal=ZONE` (the bot walks there), `--cam=x,y,z,yaw,pitch` / `--shot-cam=` (a fixed camera), `--poi-cam` (look at the mission's place), `--perf=S`, `--zombie-rack=1` / `=2` (one still zombie of every outfit, half at a time; add `--back`, `--rack-anim=walk|attack|run|...` to hold a pose), `--body-rack` (the generic male and female bodies and the skeleton, same `--back` / `--rack-anim`), `--outfit-rack=1..3` (three outfit models each, as a man and a woman side by side; same `--back` / `--rack-anim`).
- `tools\blender.ps1 tools\models\outfits.py` — rebuild the outfit models: the nine outfits each on the male and the female body (`assets/models/zombie_<outfit>_<m|f>.glb` + `_albedo.png` / `_emission.png`, ~20 s each, ~6 min for all; name outfits and add `--m` / `--f` for fewer, `--quick` for shapes only), previews in `references/shots/model_outfits.png`. `python tools/models/outfits.py --sketch [names] [--m|--f]` draws them flat-shaded without Blender in a few seconds, standing and bent in the game's poses (walk, attack, run, windup, crawl): `references/shots/sketch_outfit_<name>.png` — use it while shaping clothes. Needs Blender (portable zip unzipped in `%LOCALAPPDATA%\Programs`, or `$env:BLENDER`).
- `tools\blender.ps1 tools\models\body.py` — rebuild the generic low-poly bodies, male and female (`assets/models/zombie_body_m.glb` / `_f.glb` + textures, ~26 s for both; `--m` or `--f` for one, `--quick` shapes only in ~6 s), previews in `references/shots/model_body.png`. `python tools/models/body.py --sketch` draws them flat-shaded without Blender in seconds (`sketch_body.png`, `sketch_face.png`): use it while shaping. `python tools/models/measure.py` re-measures `references/zombies.png` into `tools/models/measured.json` (proportions, face layout, colours; overlay of every landmark in `references/shots/measure_zombies.png`). `tools\blender.ps1 tools\models\skeleton.py` rebuilds the skeleton (`assets/models/zombie_skeleton.glb`, ~12 s, previews `model_skeleton.png`); the sketch draws it too.
- `tools\godot.ps1 -- --host` — play on the Joinville city map (the default; `--map=corridor` for the test corridor). From a PowerShell one-liner pass the args as an array (`$a = @('--headless','--','--city-plan=C:/dir'); tools\godot.ps1 @a`) to redraw `references/city_plan.png` and `city_on_reference.png` (which part of the city the map covers).
- `tools\godot.ps1 -- --host --mission=mirante` — start a city mission at its POI (terminal, hospital, prefeitura, batalhao, mirante). Without `--host`, `--mission=` just picks that pin on the menu map (for menu screenshots).
- `python tools/poi_sketches.py references/poi_sketches.html` — redraw the isometric sketches of the five mission maps.
- `python tools/steps_map.py` — check `STEPS.md` (the build order) and redraw its mind map `references/steps_map.html`. `--check` only checks, `--next` lists the steps that can be started now, `--stats` counts done / total per phase.
- `python tools/trace_osm.py` — trace the OpenStreetMap tiles `references/1.png` .. `9.png` into `scripts/world/city_osm.gd` (`CityOsm`: `TILES` control points, `BUILDINGS` footprints with area and centroid, `STREETS` cells by class, `AREAS` water / park / parking / forest, `GAPS`), all in joinville.png pixels, and draw `references/osm_on_reference.png` (not committed) to check the registration; `--register` finds the control points again. Generated: don't edit by hand.
- `python tools/trace_heights.py` — re-read the hill's heights off `joinville_topography.png` into `scripts/world/city_heights.gd`. `python tools/trace_city.py` — re-classify `joinville.png` into `scripts/world/city_picture.gd` (the menu's city). Both generated files: don't edit them by hand.
- **Seeing the game without a human:** run windowed with `--bot --screenshot=... --quit-after=...` and read the PNGs. Use this to check anything visual (poses, gore, lighting) before saying it works.

## Test-driven workflow (required)
1. Write a failing test in `tests/test_*.gd` (extend `TestCase`, methods named `test_*`, `await` allowed).
2. Run `tools\test.ps1 <name>` and watch it fail for the right reason.
3. Write the code. Run the whole suite. Commit only when it's green (a pre-commit hook enforces this).
- `await new_game()` gives a real host `Game` running offline with spawning off. `spy(g)` records every hook fired; `count(calls, &"on_x")` counts them. `wait_until(cond, timeout)`, `frames(n)`, `seconds(s)` for time.
- Test behaviour through the same entry points the game uses: `g.host_interact`, `g.hit_zombie`, `g.resolve_shot`, `g.damage_player`, `g.spawn_zombie`, `g.director.spawn_horde`.
- Random things (leap cooldown, stagger chance, zombie scale) must be pinned in tests, e.g. `z.leap_cd = 0.0`. A test that passes 9 times in 10 is a bug.
- A bug found by eye (screenshot) gets a test before the fix.

## Where things are
- `scripts/hooks.gd` — **the gameplay script.** Mission hooks (`on_mission_started` fires when a mission is hosted; `on_objective_reached`, `on_extraction_ready`, `on_extracted`, `on_mission_failed`, `on_checkpoint_reached` come from `MissionRules`, `on_noise` from `Game.make_noise`; `on_player_downed`, `on_player_revived` come from `Game.down_player` / `revive_player`). `on_low_hp`, `on_right_click(target)` → `on_right_click_door` / `on_right_click_lootbox`, `on_right_click_ammo_box` / `on_right_click_ammo_crate`, `on_ammo_picked_up`, `on_loot_received`, `on_player_damaged`, `on_player_died`, `on_zombie_hit`, `on_limb_severed`, `on_zombie_killed`, `on_zombie_leap_landed`, `on_horde_incoming`, `on_door_broken`, `on_chat`, `on_ping`. Host-only. New gameplay reactions go here, not in `game.gd`.
- `scripts/config.gd` — every tuning number. Never inline numbers. Per-gun numbers are in `scripts/weapons.gd`.
- `scripts/settings.gd` (autoload `Settings`) — what the player chose: sensitivity, FOV, aim toggle, volume per bus, graphics tier, fps cap, window, keys, name. `Settings.get_value(key)` / `set_value` / `set_key`, `changed(key)`; kept in `user://settings.cfg`. Tests run on defaults and never touch the real file.
- `scripts/balance.gd` — the balance sheet (shots and seconds to kill, DPS, effective range); `tests/test_balance.gd` holds the rules the numbers must keep.
- `scripts/budget.gd` — counts what a map costs to draw without a screen; `Config.BUDGET` is the limit per map, and the same test proves the host tick with a full horde and the size of a full snapshot.
- `scripts/bot.gd` — the test player: aims, shoots, walks to a zone, opens doors, backs off. `Bot.SCENARIOS` are whole playthroughs run by `tests/test_bot_scenarios.gd` at 8x time (`Bot.run`).
- `scripts/weapons.gd` — the nine guns (damage, fire rate, magazine, reload, spread, recoil, zoom, sprint carry) plus `kick` (random recoil) and `scatter`, and the eight calibres (`Weapons.Ammo`, `AMMO`: name, starting reserve, cap, carton size, stripe colour; `GUN_AMMO` says which gun eats which). `weapon_state.gd` — magazine / reload / draw timers and the reserve per calibre for one player, no nodes (infinite until `limit(start)` is called). `viewmodel.gd` — the first-person gun and arms: aim, sprint carry, reload, recoil, bolt and pump, the muzzle flash (`scripts/fx/muzzle_flash.gd`: a star of quads shaped by `Weapons.flash_shape`), its short warm light, smoke puffs (`smoke` signal → `Game.muzzle_smoke`) and a hot barrel's shimmer and wisp. Handling: each part of a reload (release, out, in, slap, and the charging handle on an empty one), a shotgun's shells and pump, a bolt's four moves (the eye leaves the scope: `scope_break`) says so once through `Viewmodel.handling`, and `Game` plays the "h_" sound; the old magazine falls (`mag_dropped`, into `Casings`); F inspects the gun (`inspect()`); idle breathing and grip shifts; the last `LOW_AMMO_ROUNDS` sound thinner with a click. Other players' shots reach every peer as `Game.shot_seen` (their gun flashes, a puff, the shot heard where they are, a tracer to where the bullet stopped, a whiz and a flinch if it passed your head). Tracers are `scripts/fx/tracers.gd` (`game.tracers`): every shot of theirs, every third of yours, coloured by calibre, a fan for shotguns, a lingering vapour line for snipers. Spent cases are `scripts/fx/casings.gd` (`game.casings`): thrown from each gun's port its own way (`Weapons.GUN_EJECT`) when the action works (`Viewmodel.eject`), two bounces with a tink, then they lie and sink away. `scripts/models/guns.gd` — the gun models.
- `scripts/loadout.gd` — what a player carries: two primaries, a sidearm, a melee slot (`Loadout.Slot`), no nodes. `Loadout.all()` on test maps and in free play (every gun, keys 1-9 pick by gun), `Loadout.pistol()` on a mission (keys follow slots). The host has one per player (`players[id].loadout`), the player their own; `Game.give_weapon` swaps when the slots are full and the old gun goes to the ground as a dropped `WeaponPickup` with its magazine count (`Game.drop_weapon`, `on_weapon_dropped`). Q is the last-weapon key. Draw time per gun is `Weapons.GUN_DRAW`.
- `scripts/inventory.gd` — what a player carries besides guns, no nodes: counted stacks with caps (medkit, bandage, painkillers, planks), throwables in `Config.THROWABLE_SLOTS` kinds (frag, molotov, flashbang, lure; nothing hands them out until S093), keys by id (`add_key` / `has_key`), `quick_heal()`, the wheel's eight wedges (`wheel()`, `wedge_at`), `transfer_to` (a looted backpack), `get_state` / `apply_state` with plain strings. The host keeps one per player (`players[id].inventory`: `Game.give_item`, `give_key`, `inventory_room`, `can_use_item`, `use_item`); the player's copy (`local_player.inventory`) is replaced by `inventory_changed` after every change and only feeds the wheel and HUD. What an item *does* is `GameHooks.on_item_used` (medkit and bandage heal at once for now; painkillers and throwables do nothing yet). Keys: H quick-heal, G quick-throw (the selected throwable, the player's own choice), hold Tab for the wheel (`scripts/item_wheel.gd`: the mouse moves a pointer instead of the view, release picks; `item_wheel_view.gd` draws it with box-drawn icons from `item_icons.gd`, the lit one hopping; `--wheel` shows it). Lootboxes put their medkit in the inventory and stay shut when it is full. A dead player's inventory goes to a `Backpack` (`scripts/world/backpack.gd`, `Game.drop_backpack`, capped by `Config.BACKPACKS_MAX`, built from its state by late joiners like other drops) that anyone can loot; what does not fit stays in it. Hooks `on_item_picked_up`, `on_key_picked_up`, `on_item_used`, `on_backpack_dropped`, `on_right_click_backpack`.
- `scripts/player_status.gd` — wounds and what is being put on, no nodes (`players[id].status`; the player's copy `local_player.status` comes by `status_changed`): `hurt(roll)` opens a wound when a zombie's hit rolls under `Config.BLEED_CHANCE` (`Game.damage_player(id, n, zombie, bleed_roll)`: pass the roll in tests, -1 rolls), up to `BLEED_MAX`, `bleed_damage(dt)` ticks `BLEED_DAMAGE` HP per wound every `BLEED_INTERVAL` (`Game.tick_status`, run by the host loop; call it yourself in tests after `g.set_physics_process(false)`). The look: while something is put on the gun goes down and the hands wrap it (`Viewmodel.heal`, `heal_hands`, `--pose=heal`), others see `Humanoid.Anim.HEAL` (`RemotePlayer.anim_for`); bleeding players leave drops on the floor on every peer (`BleedTrail`, `Game.update_drips`), the bleeding player sees blood creep up the screen's lower edge (`BleedDrops`) and hears a heartbeat at low HP (`Heartbeat`). Healing takes time: `Game.use_item` begins it (`Inventory.use_time`), the item leaves the pack and `on_item_used` heals only when the time is up; any damage (`Game.cancel_use`) or a sprint (`LocalPlayer.check_use_cancel`) cancels it and the item stays. Medkit and bandage stop the bleeding; painkillers add `Health.temp` (temporary HP that soaks damage first and wears off, `Health.total()` is what the HUD and snapshots show). The host sets `PlayerWire.ACTION_BLEED` / `ACTION_HEAL` in snapshots (a client may only say crouch and air). Hooks `on_player_bleeding`, `on_player_healed`, `on_item_use_cancelled`.
- **Downed and revive** (also in `PlayerStatus`: `downed`, `down_left`, `revive_left`, host-only `revive_target`, `invuln`): `Health.died` calls `Game._hp_zero`: with another player still standing (not in `rules.out`) the player goes down (`down_player`: out of the fight for `rules`, crawling at `DOWNED_SPEED`, the pistol only, bleeding out over `DOWNED_TIME`, every HP of damage costs `DOWNED_DAMAGE_SECONDS`), otherwise they die at once. `kill_player(id)` is the way to a real death (it fires `on_player_died`: backpack, respawn or stay out); in tests a plain `damage_player(1, 9999)` with a guest standing only downs. A helper holds right-click within `REVIVE_RANGE` of a downed teammate (`downed_teammate_near`, `start_revive` / `client_revive`): it is a use of `&"revive"` taking `REVIVE_SECONDS`, cancelled like any use (damage, sprint, walking off, letting go, the downed one dying), and the downed one's bleed-out waits meanwhile. Done: `revive_player` (`REVIVE_HP`, `REVIVE_INVULN`, back in the fight). Zombies (`nearest_player`) go for the standing and only finish a downed player when no standing one is as close (`DOWNED_FINISH_RANGE`); everyone out fails the mission as before. Snapshots carry `PlayerWire.ACTION_DOWNED`. The look: your view drops to the floor, tilts and greys as the clock runs (`LocalPlayer.step_down_view`, `Hud.grey_for`), and rises back up over `GETUP_TIME`; others see `Humanoid.Anim.DOWNED` (propped on an arm, reaching out when you stand within `REACH_RANGE`), `CRAWL` when moving and `GETUP` after (`RemotePlayer.animate`); a ring round the crosshair fills during a revive or a heal (`ProgressRing`, `Hud.ring_for`). A checkpoint gets the downed up like the dead.
- **Death and spectating:** the map's `respawn` says how the dead come back: `true` at once, `false` never, `"checkpoint"`, or seconds (`MapData.respawn`, `respawn_after`, `respawn_checkpoint`, handed to `MissionRules.start`). When they do not come back at once `Game.mark_dead` makes them `PlayerStatus.dead` (out for the rules, `respawn_left` counts down in `tick_status` and `respawn_player` brings them back; a checkpoint does the same; `on_player_respawned`): they cannot shoot, use, interact or be hurt, their body stays put and the others do not see it (`PlayerWire.ACTION_DEAD` hides the `RemotePlayer`). Their body falls where they died on every peer (`Game.player_body`, a ragdoll of their look) and zombies within `FEED_RANGE` go to feed on it (`Zombie.feed_at`, `State.FEED`) until someone alive comes near (`--feed`). Coming back is a drop off a truck bed (`LocalPlayer.arrive`, `Fx.Kind.ARRIVAL` for the others). Their own game spectates (`scripts/spectator.gd`, no nodes: who is followed, cycled with fire / aim, a camera behind and above them that eases after them, or a slow orbit of the body with nobody left; `Game.spectate_candidates` / `_update_spectating` / `spectate_text` feed it). `RemotePlayer.hp` and `mag` (their magazine) come from snapshots. Other players' bodies: `PlayerWire.ACTION_*` say crouch, air, aim, reload, shove, throw, vault (the client's own) and heal, bleed, downed, dead (the host's); `RemotePlayer.animate` picks the legs' `Humanoid.Anim` and the arms' `Humanoid.Upper` (layered by `_write_upper`), the head and a shouldered gun follow `look_pitch`, each shot kicks (`rig.kick`); a death falls the way the last blow pushed. `--survivor-rack` shows them. Chat and pings work for everyone, the dead too: T opens the chat line (`Hud.open_chat`, `Game.say` → `host_chat`), Z pings where you look (`Game.ping` → `host_ping`, a marker for `Config.PING_TIME`).
- `scripts/camera_feel.gd` — how the view moves (`local_player.feel`, no nodes): a figure-eight bob in step with the feet, the gun lagging the mouse on a spring (more for heavy guns, `Viewmodel.feel_sway`), a lean into strafes, FOV wider when sprinting and pinched by a sniper shot, shakes mixed and capped (`add_shake`: hits via `Game.got_hit`, explosions and leapers via `Game.shake_near`, the helicopter as `rumble`), all scaled by the `camera_motion` setting. Recoil is a spring on `LocalPlayer.punch` (`kick_view`, `step_recoil`).
- `scripts/move_state.gd` — the player's body, no nodes: stamina (sprint drains, rest refills, running dry leaves you winded and walking), crouch (lower capsule and camera, slower, steadier, quieter: `step_loudness`), coyote time, the landing dip, fall height (the host takes the HP: `Game.player_fell`), and the vault over waist-high cover (`LocalPlayer.try_vault`, when sprinting into it). Heavy guns sprint slower (`Weapons.GUN_SPRINT`). The bot never tires.
- **Noise:** every loud thing calls `Game.make_noise(position, loudness, by)` on the host (shots by gun: `Weapons.GUN_LOUDNESS`, a broken door, sprinting players; `loudness` is the metres it carries). Zombies in earshot walk to the spot and stand there (`Zombie.hear`, `investigating()`), not to the player, unless one is within `Config.ZOMBIE_NOTICE_RANGE`; the director's `heat` rises and a full meter brings the next horde sooner; `on_noise` fires. `--noise` draws the rings.
- `scripts/mission_rules.gd` — **the mission's rules** (`game.rules`, host): runs the map's objective list in order (reach a zone by any / all, hold it, survive waves or a time, interact with a thing by `iid`, extract), fires the mission hooks, fails on a `time_limit` or when everyone is out (`set_out`; with `respawn` off in the data the dead stay out). Peers get `MissionRules.state()` on change (`mission_state`, also in `welcome`) as `Game.mission_view` and count its clock themselves; the HUD shows it top centre. The corridor has a two-step list as the test bed. In tests, `g.set_physics_process(false)` then move `g.players[id].pos` and call `g.rules.step(dt)`.
- `scripts/fx/extraction_zone.gd` — the open way out's look on every peer (green flare smoke column leaning with the wind, a pulsing ring of light strips, sparks rising), built by `Game._update_extraction` from `mission_view.zone`. The HUD counts the extraction down in big numerals with a rising beep for the last five seconds, then fades to white (red on failure) and shows the end screen.
- **Checkpoints:** any `checkpoint` zone a player walks into counts once (`MissionRules._check_checkpoints`, `on_checkpoint_reached`): the dead respawn there from then on, players who were out come back, crates with `unlock` set to it open, the director goes quiet for `Config.CHECKPOINT_CALM`. Its look (lit tent or safe-room door, a painted arrow on the way) comes from the zone's data (`scripts/world/checkpoint_look.gd`).
- `scripts/score.gd` — what each player did (`game.score`, host): kills, headshots, limbs, damage taken, revives, shots and hits, distance; counted from the hooks and the shot code; titles (Sharpshooter, Medic, Untouched, Last one standing). When the mission ends `Game.match_over` saves a won run's time in `user://records.cfg` (`scripts/records.gd`, per mission and difficulty; tests set `Records.path`) and sends `Score.summary` to every peer; the end screen counts the rows up. Retry (host) restarts the same match.
- **Defending:** a `survive` objective with `waves` sends each wave (size, types, closets, a calm `gap` with a countdown before it) once the last is dead, bigger for every living player (`Config.WAVE_PER_PLAYER`) and from one more closet each time; with `heli` seconds the last wave is topped up until the helicopter is down (`HordeDirector.spawn_wave`). **The helicopter:** `scripts/heli_flight.gd` (`HeliFlight`, no nodes) is its whole flight worked out from the landing point, the heading it comes from and the time (in high, one circle, a spiral down with a nose-up flare, onto the skids, waiting, then `depart_at` climbs it away), so the host only sends those numbers (`Game.call_heli` → `heli_started`, `heli_state` in `welcome`); `scripts/world/helicopter.gd` (`Helicopter`) is the look (rotor blur and droop, sliding doors, skids, nav lights, strobe, sweeping beacon, door gunner; `SOUNDS` names for S087). `Game.step_heli` flies it on every peer, blows dust and shakes the view under it; on the host the door gunner shoots the nearest zombie while it is low and players who reach `door_point()` are sat inside (`LocalPlayer.seat`); once everyone standing is aboard it lifts off. Hooks `on_heli_boarded`, `on_heli_departed`. `--heli[=S]` lands one in front of you. The HUD shows the wave, zombies left and the clocks; a siren sounds on every peer when a wave starts.
- `scripts/difficulty.gd` — easy / normal / hard / nightmare as multipliers (zombie HP, their damage, runner share, horde and wave size, ammo found) and two rules (nightmare: no HUD markers, friendly fire). `Game.difficulty` (host, `--difficulty=`), sent in `welcome`; `game.mult(key)` reads it. Hordes also grow with the players alive.
- **Shove** (V, any gun): `LocalPlayer.try_shove` (stamina, one swing at a time, `Viewmodel.shove` pull-back / thrust / overshoot) → `Game.host_shove`: zombies in a cone in reach are knocked back (`Zombie.shove`), staggered, a leaper's wind-up broken, a little torso damage, `on_zombie_shoved`; `shove_landed` thuds and puffs on every peer and jolts the shover's view.
- `scripts/game.gd` — the match: RPCs, host loop, shots, snapshots, turning host events into gore on every peer.
- `scripts/zombie.gd` — types (WALKER, RUNNER, LEAPER), state machine (CHASE, ATTACK, WINDUP, LEAP, LAND, STAGGER), per-part damage, AI. `scripts/horde_director.gd` — the pace of the match (host): four states CALM / BUILD / PEAK / RELAX driven by `stress` (0..1: `hooks.on_player_damaged` → `director.hurt`, zombies within `Config.STRESS_NEAR` of a living player, ammo low on limited-ammo maps; fades by `STRESS_DECAY`); BUILD runs the next horde's clock (`_horde_timer`, faster when calm, sooner when noise fills `heat`) and sends a straggler now and then, PEAK streams a horde (`stream_horde`: one zombie every `HORDE_STREAM_GAP` out of one closet, each told the closet's route) until most of it is dead, RELAX waits for calm. `pick_closet` only returns closets no living player can see (`map.sees` and `is_direct`) or is within `SPAWN_MIN_DIST` of (else the farthest), `pick_type` keeps types under `Config.SPECIAL_BUDGET`, wanderers (`zombie_wanderers` in the map data) stand `Zombie.idle` until a player comes within `ZOMBIE_NOTICE_RANGE`, a noise or a hit, and zombies far from everyone for `STRAGGLER_TIME` are moved to the hidden closet nearest the objective. Its own `rng` (tests seed it); `spawn_horde` (all at once) and `spawn_wave` (defend objective) are unchanged. Hook `on_pacing_changed`. In tests `g.set_physics_process(false)` and call `g.director.step(dt)`; `--director` prints it on the HUD.
- Guns over the network: clients send `client_shoot(origin, dir, weapon)`; the host uses that gun's damage, pellets and fire-rate limit, and puts the weapon id in the player snapshot so others see the right model. Magazines are client-side for now. **Ammo:** a map with `infinite_ammo` off (no map yet; `--limited-ammo` or `new_game(map, mission, true)` forces it) starts everyone on `map.starting_ammo()`; the client tells the host what each reload took (`client_ammo_used`, once per reload, never in snapshots), the host keeps `players[id].reserve` and is the only one who adds to it (`Game.give_ammo` → `got_ammo`). `Game.ammo_of(id, type)` is -1 where ammo is infinite.
- **Character models** (`tools/models/`): `poly.py` (the low-poly kit: rings lofted into prisms, blocks, a tag per face, optional skinning data per point), `pipeline.py` (Blender: mesh from triangles with vertex groups and the piece-id UV, smart UVs, bake position / normal / piece / tag / AO per texel, rig on the game's joints and the helpers `rig.BONES`, export .glb without materials), `rig.py` (the skeleton with its rest positions, and a numpy copy of how `Humanoid._apply` poses it, for sketches), `noise.py` (the painters' noise). In the game `scripts/models/character_model.gd` (`CharacterModel`) loads a model once (mesh, a Skin bound to the game's joints by name, material with albedo and an emission map for the eyes, and a rigid copy of each segment cut from the mesh: by the piece id each point carries in the model's second UV channel when it has one, else by the joint that moves it most) and `Humanoid.create_model` builds a rig on it: the same joint nodes and animation, a `skeleton` whose bone poses copy the joints in `_apply`, the skinned `body_mesh`, and the segments' rigid copies hidden on their joints. `sever` shrinks the part's bone to nothing and shows its copy (the gib); `take_all` hides the skin and shows the copies (the ragdoll). The model PNGs' `.import` files are committed (VRAM compressed, mipmaps).
- **Generic bodies** (`tools/models/body.py`, `CharacterModel.body(female)` / `BODY_M` / `BODY_F`): no clothes: what the outfits are built on. Made with `poly.py` (low-poly kit: rings lofted into prisms, blocks, every face tagged skin / eye / socket / mouth / teeth / lip / hair / brow / wound; never a curve, flat-shaded), not SDFs. One closed piece per joint (head with neck and hair, upper arm, forearm with hand, thigh, shin with foot), each ending in a faceted ball round its joint; clothes are meant to hide where pieces meet. The shoulder belongs to the torso: a ledge sloping from the neck out over the arm, whose top is a low dome tucked under it (no bump). The torso is two pieces, chest (spine) and pelvis (hips), sharing one ring along an upside-down V (`seam_y`: high mid-belly, level with the hip joints at the sides where the spine's turn moves little); that ring is weighted half and half, so the break stays closed in any hunch. Bones from `skeleton.py` stick out of the wounds a gib shows (neck vertebra, femur) and stay hidden while attached. `skeleton.py` is the whole skeleton on the same pieces and joints (`CharacterModel.skeleton()`; skull = the head's rings pulled in, so its sockets sit behind the eyes), fitted inside the male body (`tests/test_skeleton_model.gd`). The head is a 16-point ring loft whose face is points moved: socket pushed in, a V brow overhanging it (the angry look), slanted glowing eye slits, a sunk mouth shaped as a downturned arch with teeth. The face's layout, hand size and colours come from `measured.json`; male and female differ only in parameters (`MALE` / `FEMALE`). Limits: the game's shoulder joints (±0.33) make the bodies broad, so the arms hang `arm_in` inside them; the head hitbox (top at 1.88 m) caps the head at ~0.33 m. `tests/test_body_model.gd` holds the look (flat faces, closed parts, sizes, female narrower at waist and shoulders).
- **Outfits** (`tools/models/clothes.py`, `outfits.py`; `CharacterModel.outfit(name, female)`): every walking zombie is a model, its outfit's clothes on the male or the female body (`Characters.is_female(id, outfit)` from the id, `FEMALE_SHARE` per outfit; the feral leaper keeps the round body). `clothes.py` is the garment kit: `top` (a shirt, jacket or coat: long / short / no sleeves, crew / collar / high neck, tucked or hanging over the trousers, an open front showing what is under it), `pants` (long or shorts, a belt), `shoe` (shoe, sneaker, boot), `hat` (cap, hard hat, helmet, fire helmet, nurse's cap). A garment is fitted by slicing the body (`Fit.outline`: the convex hull of the body at a height, pushed out by the garment's ease) and is one continuous surface: the sleeve grows out of the shirt's armhole, both legs out of the trousers' seat. Under it the body is cut away (`body_under`); what is left (head, hands, bare forearms) is closed inside the clothes, and every opening of a garment turns in under what comes out of it. Bending: each ring of cloth rides one bone, nothing pinches; the ring at a limb joint rides a helper bone that turns half as far (`shoulder_r_mid`, `elbow_r_mid`, `hip_r_mid`, `knee_r_mid`, set in `Humanoid._apply` from `CharacterModel.HELPER_OF`), the armhole's own points follow the arm a little (`clothes.TUNE`, tuned against the poses: count folded faces in the sketch's poses before changing it). Pieces: every point says which rigid piece it goes with (`Mesh.vdata`, then the .glb's second UV channel, `CharacterModel.SEGMENT_IDS`); a garment is cut at the limb's first ring below a joint, that ring twice (once per piece), each closed by a wound, so every piece of every outfit is a closed surface (`tests/test_outfit_models.gd` checks). A severed limb's helper stays at rest, so the stump is the cloth's ring closed by its wound. The outfit material is double-sided: cloth folded over at a hard bend still shows cloth. Plain colours, one per garment part (`OUTFITS[..].colours`); blood and dirt painted by position like the bodies'.
- `scripts/models/humanoid.gd` — jointed rig + procedural animation, and the round body (style of `references/zombies.png`): every part is a smooth loft through the ring tables at the top (`Humanoid.shape(name)`, built once and shared), with a face (ears, nose, brows; a zombie's dark sockets, glowing eyes, gaping mouth with teeth; a living face's eyes and brows). `chest(x, y)` / `back` / `face` give points on the surface for placing badges or glasses. `characters.gd` — looks: zombie outfits (civilian, worker, nurse, doctor, cop, soldier, firefighter, office, prisoner; leapers are feral) and the survivor, as style keys: `<part>_paint` (a face-by-face colour region: clothes, vests, stripes, camo), `<part>_stains` (blood lying on the surface with drips), `<part>_extras` (hats, pouches, badges: box / ball / dome / tube / `hair_cap`). `mesh_kit.gd` — `Builder` (SurfaceTool boxes/cylinders for props and maps) and, for characters, `Shape` (cached geometry: `loft`, `unit`) and `Body` (packed arrays: `add` with paint, `stain`, `part`, one mesh per body part). A zombie builds in ~1.5 ms; `tests/test_zombie_models.gd` holds that and the look.
- `scripts/fx/gore.gd`, `ragdoll.gd` — blood, stains, spurts, gibs, chunks, ragdolls, corpses. All capped.
- `scripts/world/surface.gd` — what things are made of (`Surface.Kind`: concrete, asphalt, brick, metal, wood, glass, dirt, grass, water, flesh, tile): `Surface.tag(shape_or_body, kind)` when building collision, `Surface.of_hit(hit)` from a ray (untagged is concrete, a zombie's hitbox flesh), `PENETRATION` for later. A bullet into the world plays `Fx.Kind.IMPACT` with the surface as `arg` (each its own dust, chips, sparks, splinters, crack, splash, and a hole lying on the surface; a shotgun one puff for the pattern and a hole per pellet).
- `scripts/fx/fx.gd` — **the effects kit** (`game.fx`): pooled particles (`burst` on the CHIP / GLOW / SMOKE layers), short lights (`light`), surface marks (`decal`), ribbons (`trail`), all capped by `Config.FX_MAX_*`. Named effects are `Fx.Kind`; the host shows one on every peer with `game.play_fx(kind, pos, dir, size)`. A new effect = a name in `Fx.Kind` and `NAMES` plus a branch in `Fx.play`; check it with `--fx-rack`.
- `scripts/gun_voice.gd` — every gun's own shot (`GunVoice.RECIPES`: crack, body, rumble, click, buzz, echo), a far version without the crack and a suppressed one, the room's tail by place (`Game.place_at`: indoors, street, open hill) and a seeded variation per shot; `Game._fire` and `shot_seen` play them. The old single `gunshot` sound stays registered for tests.
- `scripts/sfx.gd` — **every sound, made in code.** `Sfx.play(name, position, pitch_jitter)` in the world, `Sfx.play_ui(name)` in your head. A new sound = `Sfx.register(name, bus, func(): return <samples>)` built from the primitives there (noise, tones, FM, envelopes, filters, comb, clip, crush, mix). Voices are pooled (`Config.SFX_VOICES`); the farthest gives way. Buses: Master, Guns, Zombies, World, UI, Music.

## Rules that keep it working
- **Detail:** anything people look at is an element made alone on its rack, in look-and-fix rounds against references, to the level of the zombie models; never plain boxes. Places only assemble finished elements. See "Detail and iteration" in `STEPS.md`.
- **Authority:** the host decides everything that matters (zombie HP, limbs, deaths, doors, loot, player HP). Clients send position, shots, right-clicks. Hooks run on the host only.
- **Gore is cosmetic and local.** The host sends *what happened* (`zombie_fx`: HIT / SEVER / DIE with part, position, direction); each peer makes its own blood and ragdolls. Never sync ragdoll physics.
- **Snapshots must fit one packet** (< ~1392 bytes): zombies go through `ZombieWire` (13 bytes each), players through `PlayerWire` (26 bytes each). Eight players and a full horde are 1000 bytes. Don't add fields casually; `tests/test_budget.gd` builds the worst case.
- **Interactables** sync through `get_state()` / `apply_state()`; ids (`iid`) are fixed in the map's data (`map_areas.gd`) and identical on every peer. Late joiners get all states in `welcome`. Things dropped during a match (`Game.drop_ammo_box`) get ids from `Config.DROP_IID_BASE` up and a state that says where they lie, so a peer that has never seen one builds it from the state (`Game._apply_interact_state`); they are capped (`Config.AMMO_DROPS_MAX`).
- **Models:** stand on y=0, face **-Z**, metres. Positive limb rotation swings forward; pose "PITCH" channels lean forward. Yaw toward a direction: `atan2(-dir.x, -dir.z)`.
- **Zombie outfits are looks only and never sent:** `Characters.outfit_for(id, type)` picks from the zombie id, so every peer agrees. Never use `randf` for looks (`Characters._r(id, k)` and `MeshKit.speckle` are the deterministic dice). Walking zombies wear their outfit's model (male or female, also from the id: `Characters.is_female`); on the round body (corpses, leapers, survivors) clothes are paint, stains and extras merged into the body part's own mesh (`head_extras`, `torso_paint`, `thigh_stains`, ...), so they cost no draw calls and a hat leaves with the head. Hitbox sizes (`segs[..].size`) are gameplay: the round body keeps the old ones.
- **Guns:** origin near the trigger, barrel along **-Z**. Vertex colour alpha = how metallic the part is (`Guns.material()`). The magazine and the action are separate meshes because they move. A new gun = an entry in `Weapons.DEFS` + a `_name()` builder in `guns.gd`; check it with `--gun-rack` and `--weapon=N --pose=aim`.
- **Viewmodel:** poses are weights eased 0..1 and blended (same idea as the zombie rig); never set `pivot` directly from gameplay code. Right mouse uses a door/lootbox if one is in reach, otherwise aims (`Game.right_click_is_use`).
- **Animation:** add a state by adding to `Humanoid.Anim` and writing its goal pose in `_write_goal`. Never set joint rotations directly: the rig eases toward the goal, which is what makes transitions smooth. A legless rig plays every state lying down.
- **Timers:** never capture a node in a timer lambda (it may be freed first). Use `Gore._later(delay, node, func(n): ...)` or connect a method directly.
- **Effects and sounds are pooled:** build them from `Fx` and `Sfx`, never `new()` a particle node, light or audio player in a fight.
- **Performance (144 fps on laptops):** one mesh per body part via `MeshKit.Builder`; floor stains are one MultiMesh; only two lamps cast shadows and the moon doesn't. Watch the "draws" number bottom-right.
- **GDScript typing:** values read from a Dictionary/Array are Variant. Write `var x: Type = dict.key`, not `:=`.
- After adding a script with `class_name`, the class cache must refresh: `tools\test.ps1` does it (`--import`); do the same before running the game from the command line.
